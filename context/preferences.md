# Working preferences

This is a starting point. Copy it into your project's context and replace it with your own preferences.

- Language: write in the language of the existing documents; answer in the language the user writes in.
- Communication: clear, practical updates and visible results; say what was verified and what was not.
- Work tracking: read the story and its acceptance criteria before starting; move it to `doing`, then to
  `review` when finished. `done` is the user's call, after they have checked the result.
- Changes: keep related changes together and run the project's checks before committing; never commit when
  a check fails, and report the failure instead.
- Memory: search the project's knowledge and processes before a task; note what is worth keeping, not a log
  of every action.
- Permissions: choose the level appropriate for each task; do not infer a preference for bypassing approvals.
- Restarts: ask before interrupting a running application or agent chat. In Workstream, restarting the app
  ends the sessions of its chats.
